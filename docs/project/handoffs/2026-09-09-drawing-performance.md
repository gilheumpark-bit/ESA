# 2026-09-09 도면 처리 성능 최적화

## 기준과 변경 범위

출발점은 PR #71의 `9e2603a7aa04b76d7c1e5555b780488781a9d042`다. 모델·추론 수준·해상도·기호/선/문자/논리/전체 감사의 역할·판정 임계값·호출 예산은 바꾸지 않는다. 같은 분석을 준비하고 조립하는 불필요한 작업을 줄이는 변경이다. `main` 병합과 운영 배포는 포함하지 않는다.

## 구현한 최적화

| 경로 | 변경 |
|---|---|
| `prepareLazyPrecisionRegions` | 기존 5개 이미지 변형과 구획 좌표 계획을 유지하되 PNG 구획 이미지는 실제 선택된 것만 생성한다. 빈 이미지를 대체 입력으로 사용하지 않는다. |
| `runDrawingCouncil` | 메타데이터를 먼저 검증하고, 선택한 구획의 픽셀을 준비한 뒤 원래 역할에 전달한다. 구획 준비/주석 작업은 2개 동시 실행으로 제한한다. 전체 선행 판독과 최종 감사 순서는 유지한다. |
| `createRasterPreparationCache` | 한 문서 실행 내부에서 동일 페이지의 변형/구획 준비를 재사용한다. MIME과 원본 내용 해시를 확인하며 최근 한 페이지만 보관한다. AI 추론 결과를 새 호출인 것처럼 재사용하지 않는다. |
| `resolveTerminalPaths` | 기기 몸체–선, 단자–선, 단자–단자의 후보 탐색에 공간 색인을 적용한다. 실제 접속·교차·충돌·몸체 관통 판정과 2px 계약은 동일하다. 불명확한 관측을 버려 거짓 연결을 만드는 최적화가 아니다. |
| 처리시간 기록 | 단계별 full/regionPreparation/precision/audit 시간과 실제 source 호출의 큐 대기·실행 시간을 구분한다. 준비시간과 최신 세 번의 페이지 시도를 보고서 데이터에 보존한다. |

픽셀 캐시는 전역·다중 사용자 캐시가 아니라 현재 실행의 한 페이지에만 속한다. 실패한 Promise는 제거하고, 이전 페이지의 늦은 실패가 새 캐시를 지우지 않도록 한다. 반환 구획은 버퍼와 좌표를 복제해 주석·전송·호출자의 변경이 캐시를 오염시키지 않는다. 취소 후에는 준비가 끝나더라도 공급자 호출에 넘기지 않는다.

구획 생성 실패는 전체 페이지에서 이미 읽은 정상 역할 결과를 지우지 않고 해당 구획/역할의 실패로 남긴다. 이때 발생하지 않은 AI 호출을 사용량으로 세지 않으며 최종 완결성을 높여 표시하지 않는다.

공간 색인은 바운딩 박스로 후보만 줄인 뒤 기존 정밀 기하 함수를 호출한다. 결과는 원래 입력 순서로 돌려줘 판정 동률 해소와 관계 ID 순서를 유지한다. 유효하지 않은 박스는 후보에서 탈락시키지 않고 전체 질의에 포함한다.

## 시간 데이터 해석

`preparationMs`는 역할 판독용 이미지 준비에 걸린 시간이다. 캐시 적중이면 해시 조회 등 재사용 비용을 포함한다. `queueMs`는 해당 단계의 작업 큐에 들어간 뒤 실행 시작까지이고, `serviceMs`는 공급자 호출·내부 재시도·응답 검증을 포함한다. 순수 모델 추론 시간이나 전체 파일 업로드 시간은 아니다.

호출이 겹쳐 실행되므로 개별 시간을 더해 문서 소요시간으로 표시하지 않는다. source ID와 시간·성공/실패 상태만 기록하고 도면 본문·모델 원문·API 키는 넣지 않는다. 측정값은 confidence나 COMPLETE 판정의 입력이 아니다.

## 검사와 재현

새 검사는 실제 Sharp 픽셀 일치, 선택되지 않은 구획 0회 생성, 캐시 동시 요청/격리/실패/오염, 취소, 선택 구획 실패 시 정상 역할 보존, 동일 역할 입력·봉투, 큐 시간 형식과 공간 색인 순서를 다룬다. 공간 색인은 결정론적 난수의 800개 사각형·300개 질의를 전수 비교와 대조한다. 기존 도면·V3·상업 보고서 회귀 검사도 유지한다.

```bash
npm ci
npx tsc --noEmit
npm run lint -- --max-warnings=0
npm test -- --ci --coverage --forceExit
node --test scripts/lib/ax-precision.node-test.mjs scripts/lib/drawing-commercial.node-test.mjs
PERF_ROUNDS=3 node --expose-gc scripts/benchmark-drawing-performance.mjs
PERF_ROUNDS=3 node --expose-gc scripts/benchmark-drawing-topology.mjs
npm run check:docs
npm run build
```

토폴로지 비교는 기준 커밋의 실제 production 모듈을 `git show`로 읽으므로 해당 Git 이력이 필요하다. 새 기하 함수를 테스트 안에 복제한 값과 비교하지 않는다. 속도 측정은 동일 runner에서 기존/개선 실행 순서를 번갈아 세 번씩 실행한 중앙값이고 모든 원시 반복값도 JSON에 남긴다. 테스트 실패를 빠른 완료로 세지 않는다.
