## 전수 목록과 실제 동작 검사의 차이

초기 코드 목록은 `src/app`의 페이지 템플릿 33개와 네이티브 링크·폼·입력·버튼 선언 361개다. **361개는 실행한 버튼 수가 아니다.** 정적 선언은 목록이고, 반복 렌더되는 계산기·기준서 항목과 로그인 뒤에만 나타나는 동작은 별도 시나리오다.

초기 Chromium 검사는 1440px·390px에서 33개 경로를 각각 방문한 66건과 발견한 내부 링크 90건이다. 동적 프로젝트·영수증 등의 경로는 없는 식별자의 실패 화면도 포함한다. 외부 링크는 실제 외부 사이트나 인증 공급자를 작동시킨 것으로 세지 않는다. 최초 검사에서 모바일 기준서 입력 영역 67px 넘침과 로그인 화면의 중복 SVG ID를 확인했다.

`e2e/frontend-public-workflows.spec.ts`는 계산기 목록에서 실제 노출된 모든 상세 폼을 열어 입력→요청→결과 영수증→재계산 전이를 확인하고, 기준서 각 그룹의 모든 상세 항목을 열고 닫는다. 실제 개수와 완료 항목은 첨부 JSON과 `CALCULATOR_CONTROLS`·`STANDARDS_CONTROLS` 로그로 남긴다. 이 폼의 결과 응답은 합성 HTTP fixture이므로 계산 공식의 정답성 근거가 아니다.

## 수리한 생산 경로

| 영역 | 결함과 수리 |
|---|---|
| 비교 계산 | 완료 후 입력을 고쳐도 과거 결과가 남거나, 시나리오 삭제·계산기 변경 중 늦은 응답이 다른 열에 들어갔다. 시나리오 고유 ID와 요청 소유권을 묶고 수정·삭제·교체 시 취소/결과 무효화를 적용했다. |
| OCR | 구조화 오류가 객체 문자열로 보이고 비JSON 실패나 초기화 뒤 늦은 결과가 노출됐다. 공통 오류 해석, 요청 취소·소유권 검사, 동일 파일 복구와 미리보기 해제를 연결했다. 수정·저장·취소·삭제 버튼도 이름을 갖는다. |
| 전체 도면 | AI 연결 확인이 오류 처리 바깥에 있어 로컬 연결 실패가 미처리 예외가 됐다. 전체 사전 확인을 기존 catch 경계에 넣었다. |
| 복사 | 클립보드 미지원·거부에서 일부 버튼이 실패했다. 수동 복사 대안을 제공하되 수동 안내를 복사 성공으로 표시하지 않는다. 비교·계산기·모바일·프로젝트·영수증 버튼에 연결했다. |
| 프로젝트 | 인증 복원이 끝나기 전에 조회하던 경쟁 조건, 실패한 초대·멤버 제거·삭제를 숨기던 catch를 수정했다. 읽기 요청 소유권, 중복 실행 억제, 현재 화면 보존, 오류·재시도와 모달 접근성 이름을 추가했다. |
| 문의 | 구조화된 전송 오류를 사람이 읽을 수 있는 메시지와 alert로 표시한다. 입력 검증·오류 후 재전송·추가 문의를 검사한다. |
| 레이아웃 | 모바일 기준서 입력의 최소 너비와 프로젝트 공유 URL/헤더를 조정했다. 여러 로고 인스턴스의 gradient ID는 React useId로 분리했다. |

## 재실행

```bash
npm ci
npm run check:docs
npx tsc --noEmit
npm run lint -- --max-warnings=0
npm test -- --ci --coverage --forceExit
npm run build
npx playwright install chromium
# 별도 셸에서 production 서버를 실행한 뒤 같은 URL을 지정한다.
BASE_URL=http://127.0.0.1:3025 npx playwright test --retries=0
BASE_URL=http://127.0.0.1:3025 node scripts/audit-frontend.mjs
```

전수 목록 JSON과 화면은 기본 `test-results/frontend-census/` 아래 생성된다. `FRONTEND_AUDIT_OUT`으로 출력 위치를 바꿀 수 있다. 결과는 Git에 넣지 않는다. PDF gate와 전체 브라우저 검사를 같은 서버에서 연속 실행하면 요청 제한 상태를 공유하므로 기존 CI처럼 독립 production 서버를 사용한다.

## 실제 운영으로 확대 해석하면 안 되는 범위

`synthetic-auth.ts`는 서명이 유효하지 않은 합성 토큰을 브라우저 저장소에 넣어 로그인 후 UI를 그린다. 실제 서버를 인증할 수 없으며, 외부 통신과 지정하지 않은 API는 차단한다. 프로덕션 인증 코드에 테스트용 우회 경로를 추가하지 않았다. 실제 Firebase 로그인, 조직 권한·DB 저장, 이메일 발송, Stripe 결제/웹훅, 외부 AI·사내 모델 서버는 별도 환경 검증이 필요하다.

물리 카메라·파일 선택기의 운영체제별 차이·Safari/Firefox·실제 프린터 출력·브라우저 보안 정책 전체는 이 Chromium 검사로 인증하지 않는다. 데이터가 없는 관리자/현장/커뮤니티 상태와 모든 사용자 권한의 조합을 전부 실행했다고 주장하지 않는다. 권한·외부 의존성이 없는 기능은 비활성/명시 오류를 확인한 범위만 기록한다. 스크린샷은 생성·보관하고 DOM/레이아웃 단언을 실행했으며, 별도의 육안 심사를 수행했다는 의미가 아니다.
