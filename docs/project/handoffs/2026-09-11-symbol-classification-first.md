# 2026-09-11 심볼 분류 우선 전략과 문맥 재사용

## 기준과 전략

기준 제품은 PR #71의 `9327c3afcd8a090be90d699c071b7d59b202700f`다. 사용자 요구는 비슷한 심볼마다 질문하지 말고 먼저 무엇으로 분류했는지 보여주라는 것이다. 기존 회사 사전과 승인 피드백을 재사용하며, 미세 형상 변화는 연결·반복 배치 또는 명시 문자 근거와 결합한다. 같은 좌표만으로 종류를 복사하지 않는다.

`원본 벡터 → 기존 정확 매칭/회사 사전 → 지원 기하의 유사 후보 → 같은 연결 역할·명시 종류 문맥 → 분류 결과/근거 → 충돌·특수 항목만 예외 검토`

이번 구현은 DXF 벡터 경로의 결정론 단계다. 래스터 이미지·PDF의 픽셀 심볼 family 비교나 VLM 호출 스케줄을 변경하지 않는다. DXF는 기존에도 벡터 전용으로 실행할 수 있었으므로 추가 모델 호출 0을 전체 AI 비용이 줄었다는 측정값으로 바꾸지 않는다.

## 결과와 검증 상태 분리

`classification`은 ESA가 어떤 종류로 분류했는지와 방법·후보·사유·대조 사례를 기록한다. 원래 `type`, V3 `confirmedType/certainty`, 정격, 결선, 수량과 계산 입력을 덮어쓰지 않는다. 유사도+문맥으로 분류됐다고 원본 전체가 완전히 해독됐거나 공학 계산 입력이 검증됐다는 뜻은 아니다.

화면은 분류 메타데이터가 있는 문서에서 분류 결과를 먼저 보여준다. 기존의 모든 미확정 항목을 첫 화면 질문지로 제시하지 않는다. 종류별 분류 수, 자동 분류 근거, 예외 필터, 원본 위치, 선택적 종류 수정을 제공한다. 이미 자동 분류된 결과도 사용자가 잘못됐다고 판단하면 수정할 수 있다. 분류 결과 화면에 일괄 승인·건별 필수 승인 요구는 없다.

원본 근거의 미확정 목록은 삭제하지 않는다. 정격·결선·실물 수량 판정이나 최종 검증 자료가 필요하면 기존 상세 범주에서 확인한다. 화면에서 제외된 질문의 수를 실제 정확도 상승이나 판독 완료율로 집계하지 않는다. CSV/인쇄는 분류와 기존 판독을 별도 행으로 보존한다. 기존 문서에 새 메타데이터가 없으면 원래 화면과 내보내기 계약을 유지한다.

## 기하와 문맥 규칙

### 기하

지원: LINE, 곡률·폭이 없는 2D POLYLINE/LWPOLYLINE, CIRCLE, ARC. 정의의 평행 이동·등비 크기·엔티티/선 끝점 순서를 정규화한다. 블록 INSERT의 위치·회전은 정의 지문과 별개지만 반복 역할 비교에서는 실제 INSERT 방향을 확인한다. 실제 블록 정의의 좌우 반전·회전까지 같은 의미라고 단정하지 않는다.

최대48개 기하 요소, 최대256개 원본 엔티티를 사용한다. 지원하지 않는 내부 INSERT/SPLINE/HATCH, 불완전 좌표, 굽은 폴리라인은 일부만 비교하지 않고 유사도 대상에서 제외한다. 기존 정확 지문 파싱은 계속한다. 암호학적 해시 문자 사이의 거리를 유사도로 사용하지 않는다.

선 끝점 접속의 차수·연결 성분·요소 수가 다르면 후보를 강제로 맞추지 않는다. 선·원·호는 일대일 대응으로 비교해 한 선이 여러 선을 설명하게 하지 않는다. 이 선 끝점 연결성은 실제 기기의 전기 단자를 완전히 인식했다는 뜻이 아니다.

### 문맥

자동 적용은 높은 형상 일치와 종류 간 분리, 최소 기하 복잡도, 추가 문맥이 모두 필요하다. 추가 문맥은 유일하게 가까운 명시적 종류 문자 또는 같은 공유 모선/반 노드에 연결된 기등록 사례 최소2개다. 반복 사례는 같은 레이어·연결 수·행/열 방향·INSERT 방향을 확인하며, 알려진 전압이 충돌하면 사용하지 않는다. 이 페이지의 회로 역할 조건은 프로젝트 revision 간 같은 슬롯이 반드시 같다는 규칙이 아니다.

예비/공란, 누전 계열, 절체, 특수 표식과 회사 사전 충돌·다른 종류 후보가 접전인 경우는 예외로 남긴다. 이름·주변 배치만으로 기기 종류나 전압/정격을 지어내지 않는다. 해석 가능한 분류 단위는 현재 SLD 종류 정본에 맞춘다. 예를 들어 breaker 분류가 MCCB/ACB/ELB의 모든 세부 사양 구분을 뜻하지 않는다.

초기 정책의 후보0.80/자동0.96/종류차이0.06은 **버전이 있는 기하 규칙 한도**다. 독립 회사 도면에서 보정된 정답 확률이 아니다. 화면에는 원시 형상 유사도임을 명시하며, 실제 고객 도면의 오분류-처리범위 분포로 향후 조정해야 한다.

## 사람 피드백과 비용

DXF 원본 정체성에 검증된 기하 descriptor를 선택 필드로 붙여 V3·정정·승인 사전으로 전달한다. 과거 hash-only 사전은 그대로 정확 매칭에 사용하되 실제 형상 벡터를 복원했다고 가장하지 않는다. 새 형상을 저장하려면 해당 원본의 재분석과 기존 종류 정정/승인 흐름을 사용한다.

판독이 시작될 때 기등록/승인된 원본 seed를 고정한다. 같은 실행에서 추론한 결과는 다른 추론의 seed로 사용하지 않는다. 사람이 수정하지 않은 자동 결과는 자동학습·golden label로 등록하지 않는다. 승인 기록의 회사 선택·철회·이력 규칙은 기존 계약을 유지한다.

사람이 seed 종류를 바꾸면 그 원본을 참조한 자동 분류는 재검토로 돌아간다. 문자·라벨 수정에서는 영향 페이지의 자동 문맥 분류를 보수적으로 무효화한다. 원본 판독 결과와 수정 이력은 보존한다.

블록 정의 descriptor는 요청 안에서 한 번 만들고, 같은 기하의 비교 결과도 재사용한다. 최대512개 기준 사례와10,000회 형상 비교 한도를 두고 한도 초과 시 후보를 잘라 경쟁 유형을 없애지 않는다. 비교 횟수·재사용 횟수·이번 단계의 모델 호출 수를 실제 결과에 남긴다. 이 수치는 현재 문서의 작업량이지 전체 서비스 비용 절감률이 아니다.

## 검증 계약

새 검사는 원래 코드 함수와 실제 dxf-parser, V3 adapter/deduplication, applyDrawingCorrection, feedback 파서와 화면/보고서를 호출한다. 합성된 의미가 알려진 블록을 사용하므로 독립 실도면 일반화 정확도를 증명하지 않는다. 정상 자동분류, 미승인/무사전, 같은위치만, 잘못된연결/레이어/방향, 특수표식, 근접문자충돌, 다른종류유사후보, 원본변경, 모델 JSON의 가짜 분류메타데이터, 반복 연산량을 구분해 검사한다.

PC1440px/모바일390px 브라우저는 분류 결과 우선 표시, 근거 펼치기, 예외 필터, 원본 이동, 선택적 분류 수정, 실패 입력 유지, CSV를 확인한다. HTTP 전송은 합성이고 실제 파서/정정 함수를 사용한다. 화면 캡처·URL·제목·수평 넘침·runtime error를 기록한다. Browser 전용 플러그인은 현재 목록에 없어 기존 Playwright 경로를 사용한다.

로컬 실행 도구의 transport timeout으로 이번 작업의 실행 검증은 GitHub Actions의 정확한 잠금 의존성과 production 서버에서 수행한다. 로컬 테스트나 캡처 육안 확인을 하지 않았다면 이를 완료했다고 보고하지 않는다. 최초 정적 검사34553909387은 신규 시험의 미사용 type import로 실패했고 이를 제거한다. 최종 통과 여부·건수·SHA는 최신 실행과 PR 검증 댓글에만 실제 확인 후 기록한다.

## 통합 검토 보강

집중 실행34554287778에서 타입·무경고 린트·심볼/피드백/기존 파서와 독립 스크립트 계약이 통과했다. 그 이전 실행의 한 실패는 선택값을 아예 기록하지 않은 review 상태를 `selectedType:undefined` 속성이 존재해야 한다고 단언한 시험이었다. 선택값이 없다는 조건을 `not.toHaveProperty`로 명확히 해 유지했다. 자동 판단을 허용하거나 임계값을 낮춘 변경이 아니다.

반복 문맥은 전체 기기 대신 고정된 기등록 seed 인덱스를 사용한다. 같은 좌표에 중복된 기기를 별도 두 근거로 세지 않는다. 승인되지 않거나 취소된 descriptor는 유사도 참조에 넣지 않는 반대 조건과, 승인 descriptor의 새 이름 변형을 명시 종류 표기로 분류하는 정상 조건을 추가했다. 최종 전체 검사와 브라우저 결과는 별도 실행으로 확인한다.
