## 내부 화면 이동 호환성

패치된 eslint-config-next가 내부 주소의 location.href/assign 네 곳을 새로 경고했다. 홈 검색·이력 예시·설정의 로그인 이동을 useRouter로 바꿔 내부 이동 때문에 앱 문서를 다시 받지 않게 했다. 홈의 진행 상태는 useTransition으로 이동 완료와 함께 해제한다. 이력 예시는 정본 calculatorHref로 올바른 분야에 연결한다. Stripe 등 외부 주소는 기존 실제 브라우저 이동을 유지했다. 새 규칙을 끄지 않았다.

새 브라우저 검사는 홈 검색과 이력 예시 세 가지에서 대상 URL과 같은 브라우저 문서의 유지를 확인하고 홈으로 돌아온 후 재실행 버튼도 확인한다. 검색/계산의 실제 외부 API 품질을 증명하지 않는다.

## 브라우저 검증 중 확인한 인증 복원 경쟁 조건

실행 `34304217958`에서 102개 브라우저 검사 중 프로젝트 생성 한 건이 실패했다. trace와 네트워크를 확인하면 제출 시점까지 초기 Firebase 사용자 복원이 끝나지 않아 `/api/projects` 요청이 전혀 없고 클라이언트의 `로그인이 필요합니다.` 오류가 표시됐다. 이어 계정 조회와 로그인 표시가 나타났다. 단순 재시도로 종결하지 않았다.

`getIdToken`·`getCurrentUser`가 공식 SDK의 `authStateReady()` 이후 현재 사용자를 읽도록 하고, 새 프로젝트 화면은 인증 확인 중 제출 폼을 열지 않도록 했다. 익명 사용자는 여전히 거부하고 토큰이나 사용자를 합성하는 production 우회는 없다. 초기 복원을 직접 지연하는 새 브라우저 검사와 토큰/프로필 조회의 여섯 단위 검사를 추가했다. 기존 생성 실패/재시도 검사도 유지한다.

## 분석 실행 순서 개선

종전에는 symbols/connections/text/logic의 전체 판독이 모두 끝나야 선택 구획을 준비하고 호출했다. 이제 기호·연결·문자의 전체 판독이 준비되면 기존 선택 규칙으로 구획을 결정하고, 독립적으로 실행 중인 logic을 기다리지 않고 정밀 판독을 시작한다.

공유 FIFO 실행 풀은 전체 판독과 정밀 판독을 합쳐 기존 공급자 동시 실행 상한을 지킨다. 전체 판독 요청은 먼저 큐에 넣으므로 문자 변형이나 logic이 정밀 구획 뒤로 밀리지 않는다. 최종 coverage-auditor는 logic과 정밀 판독이 모두 끝난 후 실행한다. logic 실패는 필수 역할 실패로 남기며 빠른 완료로 위장하지 않는다.

다음 계약은 유지한다.

- 모든 전체 문자 변형을 읽기 전에는 정밀 구획을 선택하지 않는다.
- 모델·역할별 추론·이미지·좌표·프롬프트·판독 역할·구획 선택·호출 예산·확신도 조건을 낮추지 않는다.
- 실제 시작한 source만 사용량과 실행시간에 기록한다. 취소된 대기 작업은 새 공급자 호출을 하지 않는다.
- 중단 시 완료된 정상 봉투를 보존하고, 예상하지 못한 오류로 반환할 때도 관측되지 않은 logic Promise를 남기지 않는다.
- 시간 기록의 `graphReadyMs`는 기호·연결·문자 준비 완료까지이며, `scheduling=overlap-logic-v1`로 실행 방식을 식별한다. full과 precision은 겹칠 수 있으므로 단계 시간을 단순 합산하지 않는다.
