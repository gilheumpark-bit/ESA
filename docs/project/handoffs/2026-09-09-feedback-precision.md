# 2026-09-09 사람 피드백 연계와 정격·페이지 연결 정밀도 개선

## 범위와 설계 결정

출발 제품은 PR #71의 `d73a19b5318d2a39ea80f02b62eba0429b44955b`다. 현재 도면 정정과 다음 분석용 회사 사전이 분리돼 있던 경계를 연결한다. 실제 AI를 재학습하거나 모든 도면의 정확도를 측정한 작업은 아니다. main 병합·배포·비밀값 사용은 포함하지 않는다.

첫 폐루프는 **실제 DXF 파싱 → V3 기기 종류 정정 → 재사용 후보 등록 → 명시적 검토·승인 → 같은 회사 사전의 다음 DXF 파싱 → 적용 이력 확인·취소**다. 추가 모델 호출·요금 없이 기존 벡터 분석에서 사람 지식을 재사용한다.

### 왜 이 연결부터 구현했는가

DXF 블록은 원본 기하 지문과 이름을 실제 파서에서 얻을 수 있다. 이미지 OCR의 유사 문구나 단순 기기 이름만으로 다른 도면의 기기를 확정하면 오답 전파 위험이 있다. 따라서 이번 피드백은 회사 선택 + fp2 지문 + 정규화 블록명이 모두 일치해야 한다. 영상·문자·정격·결선의 범용 사례 검색/모델 학습은 별도의 근거·승인·평가 설계가 필요하다.

NIST AI RMF Playbook의 Measure는 사용자 피드백과 override 수집, 현장 성능 측정·개선의 연결을 설명한다. 선택적 예측 연구는 확정 범위를 늘리는 것과 잘못 확정할 위험을 함께 평가한다. 이번 구현의 인증 근거나 실도면 성능 보장은 아니다.

## 피드백 구조

| 단계 | 실제 동작 |
|---|---|
| 원본 연결 | DXF blockName·blockFingerprint를 adapter·중복 병합·정정 후에도 보존한다. 서로 다른 지문이 같은 노드로 병합되면 재사용 앵커를 제거한다. |
| 후보 | 현재 유효한 기기 종류 정정만 등록한다. 원본 문서 SHA-256·정정 ID·대상 ID·이전 후보·선택값을 함께 보존한다. unknown·지원하지 않는 타입·과거 정정·원본 지문 없는 이미지 후보는 등록하지 않는다. |
| 승인 | 회사·지문·종류의 적용 범위 확인과 사유 입력 후에만 활성화한다. 현재 원본에서 이미 다른 값으로 수정한 대기 후보는 승인하지 못한다. 기존 사전/승인 규칙과 충돌하면 거부한다. |
| 다음 분석 | 해당 회사 사전의 approved 항목만 읽는다. 같은 이름만 또는 지문만 같은 경우는 새 피드백 규칙을 적용하지 않는다. 판독 기기의 properties에 feedbackIds·feedbackRevision을 남긴다. |
| 취소 | 승인 취소 이후의 분석부터 제외한다. 기존 분석·정정·결정 이력은 소급 수정하지 않는다. 취소 기록을 재승인하려면 새 정정 후보로 다시 검토한다. |
| 저장 | 기존 브라우저 회사 카탈로그에 revision·feedback을 추가해 한 번의 저장으로 활성 상태와 이력을 함께 갱신한다. JSON 반입/반출과 API multipart 파싱에서도 같은 계약을 검증한다. |

이 승인은 사용자의 **로컬 검토 결정**이며 조직의 독립 승인자·서버 RBAC·전자서명이 아니다. 회사 이름은 사전 분리 키이며 보안 경계가 아니다. 사용자 제공 JSON은 서명되지 않은 사전이다. 조직 간 서버 공유를 이번에 만들지 않았다. `goldenEligible:false`는 그대로이며 피드백을 독립 평가 정답으로 자동 승격하지 않는다.

전역 메모리·프롬프트에 사용자 수정을 주입하지 않는다. 최대 500개 피드백, 필드 길이/지문/상태/결정 순서/시간과 기존 파일·카탈로그 크기 한도를 검증한다. 손상 저장소·quota·오래된 탭 상태에서는 덮어쓰지 않는다. localStorage의 기대 스냅샷 확인은 다중 사용자 DB 트랜잭션을 대체하지 않는다.

전통적인 회사 사전의 별칭/지문 정책은 호환 유지하며, 새 피드백 규칙만 결합 일치 조건을 요구한다. 기존 매핑 편집은 새 피드백의 이력을 보존한다. 가져온 approved 기록끼리 충돌하거나 기존 매핑과 충돌하면 임의로 첫 번째를 택하지 않는다.

## 함께 수리한 정밀도 문제

### 정격을 읽는 것과 귀속을 판정하는 것을 분리

`readRatedMeasurements`는 한 명판의 모든 물리량과 원문 문자 위치를 보존한다. `22.9kV / 380V / 1000kVA`가 첫 값 하나만 남던 경로를 수정했다. 천단위 쉼표·긴 단위·단위 경계를 공통으로 해석해 kVA를 kV로 읽지 않는다.

`RatedValue.certainty`는 읽힌 값의 상태이고 `ownership`은 귀속 상태다. 같은 페이지의 유일한 확정 기기 영역 안에 포함된 문자만 기존 위치 근거로 귀속한다. 단순히 중심점이 가깝다는 이유로 귀속을 확정하지 않고 후보를 유지한다. 동률·먼 문자·잘못된 페이지 근거는 확정 귀속이 아니다. 확인된 숫자는 버리지 않는다. 후보 탐색의 120은 기존 좌표계의 탐색 반경일 뿐 물리 길이가 아니다.

귀속이 미확정이면 전체 보고서의 완료 주장에 반영하고 화면·CSV·인쇄에서 읽힘과 귀속을 구분한다. 포함 관계는 위치 기반 휴리스틱이며 모든 명판의 의미 귀속을 인증한 것은 아니다. 변압기 1차/2차와 차단기 AF/AT 역할, 표·leader line 기반 귀속 편집은 이번 범위 밖이다.

### 페이지 간 연결의 단위·입력 순서 의존 제거

가까운 첫 전압 문자열 대신 확인된 근방의 전압들을 모은다. V/kV를 같은 단위로 비교하고 kVA는 용량이므로 제외한다. 충돌 전압이 있으면 문자 배열 순서에 따라 연결이 확정되지 않는다. 같은 이름·종류·전압의 연결쌍이 여러 개면 첫 번째를 고르지 않는다. 명시적 시트 참조와 유일한 호환 기기쌍의 정상 사례는 유지한다.

이는 시트 표식의 실제 배선/단자 부착 위치까지 완전하게 해석한 변경은 아니다. 중복 표식·다중 판넬의 의미 연결과 다중 단자망 확장은 별도다.

그래프 조립 버전은 v10으로 변경해 이전 결과를 새 귀속 계약의 결과로 재사용하지 않는다. 기존 저장 문서를 자동으로 새 판정으로 바꾸지는 않는다.

## 검증과 해석

단위 검사는 실제 DXF 파서·production adapter·V3 정정·저장·JSON/API 계약·다음 파싱을 연결한다. 미승인·취소·다른 지문/이름·미선택 사전·충돌·부패 저장·초과 크기·오래된 정정을 포함한다. 기존 정상 파싱과 수정/미판독 계약도 함께 검사한다.

동일 블록을 다른 위치에 둔 12개의 **합성 반복 패턴**은 승인 전 분류 성공 0, 승인 후 12, 잘못된 타입 확정 0으로 확인했다. 같은 패턴을 알려준 뒤 다시 찾는 기능 회귀이며 독립 실도면 정확도/일반화/자동화율 100%가 아니다. 반례에서는 재사용을 차단한다. 실제 고객 도면에서 다른 원본·프로젝트를 분리해 오확정과 해결 범위·재작업 시간을 비교해야 한다.

브라우저 흐름은 `/tools/sld` → 기기 종류 정정 → 회사 지정·후보 저장 → 승인 전 다음 DXF의 unknown → 검토 승인 → 다음 DXF의 분류와 근거 → 새로고침 → 취소 → 이후 unknown → JSON 이력 반출이다. 데스크톱 1440px·모바일 390px에서 실행한다. Browser plugin이 목록에 없어 저장소의 Playwright를 사용한다. HTTP·V3 응답은 명시적 합성 fixture이고 실제 파서·정정·사전 함수를 사용한다. 실제 계정·서버 저장·외부 AI 검증을 대신하지 않는다.

## 남은 상업화 과제

범용 OCR·정격 귀속·결선 수정 사례의 다음 판독 재사용, 서버 기반 회사 승인권한·동시 편집, 피드백과 독립 평가셋 분리, 실도면 반복 오류율·검토시간 측정은 남아 있다. 이번 연결은 회사 DXF 블록 종류를 명시적으로 재사용하는 첫 완성 경로다.

안전 상수 판본 부채, UIV-001 재계산 간헐 오류, 빠른/V3 단일 작업 통합은 OPEN을 유지한다. 모든 미판독을 보류해 정확도 수치를 부풀리거나, 사람의 지식을 AI 모델 자체의 성능 향상으로 표시하지 않는다.

## 기존 실도면 스냅샷 갱신

전체 Git 이력을 확인한 첫 준비 실행 34370349937에서 기존 스냅샷(2026-08-10)이 PDF API 변경보다 오래돼 gate:snapshot이 실패했다. 코드 검사 실패나 실증 부재가 아니라 과거 응답의 최신성 문제다. 이 게이트를 삭제하거나 허용치를 바꾸지 않았다.

후속 준비 실행 34371269130에서 저장소에 있는 공개 RSC PDF 4쪽과 KIMM PDF 5·9·14·40쪽을 실제 production /api/pdf-drawing에 다시 통과시켜 다섯 응답을 갱신했다. 외부 AI는 호출하지 않았고, 결과 수량을 정답 라벨처럼 취급하지 않았다. execution-provenance.json은 원본·페이지·결과 해시, 제품 소스 해시, 이전/이후 관측 수를 함께 기록한다. 과거 응답은 Git 이력에 보존돼 있다.

스냅샷 신선도 판정은 갱신된 응답을 제품 후보 커밋에 담은 뒤 원래 gate:snapshot으로 재검사한다. 완전한 Git 이력이 없는 검사의 PASS만으로 원본 실증이 최신이라고 판단하면 안 된다.
