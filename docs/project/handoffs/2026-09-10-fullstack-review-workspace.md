# 2026-09-10 프런트·백엔드 연결과 검토 화면 개선

## 기준과 범위

출발 제품은 PR #71의 `c8740c47aaa72c7ae8d3a79b901fec080d2c30c8`이다. 이전 작업 브랜치에 작성했지만 연결하지 않은 DrawingReviewQueue와 수정 요청 검증을 실제 화면·API에 연결한다. 도면 엔진·모델·정격·결선 판정·권한·라이선스는 변경하지 않는다. main 병합과 운영 배포도 포함하지 않는다.

## 사용자 흐름

`/tools/sld → 전체 문서 분석 → 미확정 검색/사유/페이지 필터 → 원본 위치 → 후보 선택 또는 직접 수정 → 실패 시 입력 유지·재시도 → 오래된 문서면 최신 결과 조회 → CSV/인쇄`

검토할 항목이 있으면 미확정 범주를 먼저 보여준다. 검색·사유·페이지 필터와 40개씩 더 보기를 제공하며 실제 전체 미확정 수는 숨기지 않는다. 빈 검색과 미확정 없음의 의미를 구분한다. 종류·문자 근거가 있는 항목만 직접 수정하고, 결선·원본 품질 문제에는 종류를 고르는 잘못된 입력창을 제공하지 않는다.

입력은 필터나 결과 탭 전환에서 유지하며 다른 문서/작업으로 바뀌면 초기화한다. 화면 내부의 고정 높이 스크롤을 제거하고 넓은 화면에서는 원본과 결과가 각각 절반을 사용하며 원본을 고정한다. 좁은 화면은 세로로 흐르게 한다. 새 조작 대상은 최소 44px, 본문은 14px, 보조 설명은 12px로 유지하고 기존 색상 토큰을 사용한다. 새 강조 버튼은 다크에서도 읽히는 전경색 토큰을 사용한다. 외부 실증 상태를 표시하되 실제 정확도처럼 읽힐 수 있는 95% 접두어는 제거했다. 검증 데이터의 의미나 완료 판정은 바꾸지 않았다.

## 요청과 결과의 소유권

수정 요청은 JSON 타입과 각 필드 형식을 확인하고 실제 수신 UTF-8 바이트를 16KiB로 제한한다. 청크마다 객체를 쌓지 않고 고정 버퍼를 사용하며 수신은 최대 10초다. 형식·초과·중단은 400/415/413/408로 구분하고 원문·토큰은 오류에 넣지 않는다. origin·rate limit·서버 인증·작업 소유권·atomic 문서 버전 비교는 유지한다.

멱등 고유키가 이미 사용됐으면 대상·종류·값까지 같은 경우만 동일 응답을 돌려준다. 같은 키의 다른 동작은 409다. 브라우저는 같은 문서 버전과 같은 수정의 재시도에 같은 키를 사용한다. 수정 실패를 catch한 뒤 성공으로 해결하지 않고 편집기에 실패를 전달한다. 최신 결과를 명시적으로 다시 불러오는 경로도 추가했다.

작업 세대가 바뀌면 기존 클라이언트 읽기·수정 응답이 새 도면을 덮지 못한다. 복원·분석·재개·취소·정정·새로 조회에 세대 검사를 적용한다. HTTP 읽기 중단은 서버 분석 자체의 취소가 아니며 기존 명시적 분석 중단 기능을 유지한다. 상태 조회는 이전 조회 완료 후 다음 타이머를 걸어 요청 중첩을 막는다. 세션 복원 실패의 미처리 Promise도 표시 가능한 오류로 바꿨다.

## 검증 방식

로컬 Node22의 수정 요청 경계 10개 동일 조건에서 기존 라우트 2통과/8실패를 재현했고, 수정 후 요청 모듈·라우트 42건과 주변 정정/화면 계약을 합친 집중 검사 67건이 통과했다. 이 건수는 전체 신규 기능 수가 아니며 실도면 정확도나 API 부하시험을 뜻하지 않는다. 기존 소스 문자열 단언은 검사 함수가 이동한 부분만 실제 실행 단언으로 이관했다. 기존 안전 조건과 임계값을 낮추지 않았다.

로컬 production build는 성공했지만 로컬 Chromium의 loopback 접근은 ERR_BLOCKED_BY_ADMINISTRATOR로 차단됐다. 따라서 실제 디자인/브라우저 통과는 원격 production 서버의 결과와 스크린샷을 기준으로 한다. Browser plugin은 목록에 없어서 기존 Playwright 경로를 사용한다.

기준선 실행 `34427431389`에 기존 PC1440/모바일390의 홈·업로드·검토 화면이 보존돼 있다. 초기 로딩 중 fade 애니메이션이 포함된 그림을 영구적인 대비 결함이라고 해석하지 않는다. 새 화면은 애니메이션을 마친 상태로 촬영한다. 업무 화면의 정보 순서·검색·수정 오류·원본 대조·모바일 넘침을 확인하며 앱 전체 디자인을 새로 만든 작업은 아니다.

신규 e2e는 합성 HTTP 입력에 실제 applyDrawingCorrection을 사용한다. 수정 실패 입력 유지·고유키 재사용·새 도면 교체·문서 버전 갱신을 검사한다. 실제 고객 인증·DB·외부 AI 검증으로 확대 해석하지 않는다. 최종 전체 Jest/스크립트/보안/빌드/PDF/브라우저 결과와 정확한 제품 SHA는 해당 CI와 PR 댓글을 따른다. 이전 실행의 녹색 결과를 새 HEAD로 합산하지 않는다.

## 후속 화면 확인과 작업 경계

첫 통합 실행 34465672707은 전체 Jest4520, 스크립트164, 실제 PDF17, Playwright114가 통과했다. 그 화면을 직접 확인해 모바일 선택 필터 문구의 잘림과 DXF 안내가 관계도 위를 가리는 문제를 수정했다. 초기화 버튼을 모바일 별도 행으로 배치하고 DXF 설명을 그림 밖으로 옮겼다. V3라는 내부 버전 표기도 전체 문서 검토로 바꿨다.

새 문서 시작 시 이전 복원 키를 제거하고, 성공한 서버 취소는 기존 poll/run 응답의 세대까지 무효화한다. 취소 요청이 실패했을 때는 분석을 임의로 완료 처리하지 않는다. 초기화와 개발 교보재의 전체 문서 경로에도 같은 수명 관리를 적용했다. 새 두 브라우저 검사로 이전 작업 재복원과 늦은 취소 응답을 확인한다. 스크린샷은 고정 헤더 아래부터 촬영하고 실제 테마 버튼으로 밝음/어둠을 전환해 확인한다.

첫 실행의 통과와 최종 후속 커밋의 결과는 별도로 기록한다. 최종 출고는 후속 코드의 모든 검사와 PR CI를 따른다.

## 오류 문구의 테마 대비

후속 PC/모바일 밝음·어둠 스크린샷을 직접 확인하면서 어두운 배경에 기존 붉은 오류색이 낮은 대비로 남아 있는 것을 찾았다. 기존 밝은 테마 오류색은 유지하고, 도면 작업 화면에만 별도 다크 오류 전경색을 연결했다. 전역 오류 정책이나 다른 계산기 화면을 일괄 변경하지 않았다.

브라우저 캡처 시 실제 렌더된 오류 문구의 전경색과 가장 가까운 불투명 배경색으로 대비를 측정하고 4.5 미만이면 실패한다. 기준은 W3C WCAG 2.2 1.4.3의 일반 텍스트 대비다. 모든 접근성 기준을 인증한 것은 아니며 프레임워크의 숨겨진 route announcer는 검토 화면의 알림과 구분한다. 오류 문구·입력 보존·재시도 동작은 동일하다.
