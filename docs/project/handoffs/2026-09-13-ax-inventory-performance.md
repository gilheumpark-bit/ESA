# AX 기기표·누락 포함 평가·선분 정규화

## 기준과 범위

출발 main은 `ea08a41e46bf5429ac1032c94eab1783c73b8aa0`다. 이번에는 기존 자동 분류를 업무 결과에 연결하고, 그 성과를 검출 누락까지 포함해 평가하며, DXF의 단순 선분 분할 차이를 흡수한다. 전체 AX 계획의 완성이나 독립 실도면 정확도 인증이 아니다.

## 1. 업무용 기기표

`buildDrawingWorkProduct(document)`가 현재 문서로부터 기기표 읽기 모델을 만든다. 기존 확정 판독과 근거 있는 자동 분류를 구분해 사용할 수 있고, 원본 위치 없는 항목·분류 충돌·중복 식별자·미판독은 사용 가능 목록에서 제외한다. 같은 출력에 기존 판독 종류와 확정 상태, 출처, 분류 방법을 보존한다.

`/tools/sld → 분석 결과 → AX 기기표`에서 분류별 집계와 원본 이동, 기존 분류 수정 화면으로의 이동, 전체/사용 가능 CSV를 제공한다. 원본의 미확정 사유나 계산 영수증을 바꾸지 않고, 사람이 수정한 다음 문서에서 기기표를 다시 생성한다. 별도 복사본을 저장하지 않으므로 옛 수정값이 남는 상태를 만들지 않는다. 참조 기기 수정으로 무효화된 자동 분류는 기기표에서도 사용 가능 상태에서 빠진다.

**범위는 검출 심볼의 출현이다.** 같은 장비의 여러 페이지 표현, 변압기 권선, 모선 기호 등을 물리 장비 한 대와 동일시하지 않는다. CSV에는 문서 해시·버전·정책·원본 판독 상태와 범위가 포함되며 수식형 문자열은 기존 안전 CSV 함수로 처리한다. 임의의 물리 대수나 전압·전류·차단용량을 생성하지 않는다.

## 2. 선분 분할 차이의 정규화

기존 descriptor와 fp2 해시는 그대로다. 분류기 안에서만 검증된 descriptor의 비교용 복사본을 준비한다. 직선이 둘 이상의 연속 LINE으로 나뉜 경우, 차수2인 공선 중간점을 제거해 같은 형상으로 비교한다.

실제 분기·T접점, 비교 지점의 교차선, 원/호 접촉, 간격, 굴곡, 중복 겹침은 합치지 않는다. 누락된 선을 그리거나 작은 틈을 닫는 알고리즘이 아니다. 원본48개 기하 요소 한도와 지원 형상 범위도 유지한다. 같은 형상의 정규화는 요청 내 최대1,024개 캐시로 재사용하고 다른 회사·다음 요청으로 공유하지 않는다. 기존 비교 결과 memo와 후보 충돌·특수 표식 방어도 유지한다.

정규화 정책은 `collinear-degree-two-v2`, 페이지 재사용의 그래프 버전은v12다. descriptor 저장 형식은v1을 유지하므로 과거 원본 형상을 바꿔 저장하지 않는다. 전기 접속 그래프나 원래 종류는 이 정규화로 직접 수정하지 않는다.

## 3. AX 기기표 평가

`evaluateAxInventory(document, goldenLabel, context)`는 기존 엄격 공학 평가기와 별개의 기기표 평가다. 정답은 독립 입력이며, 문서 해시가 다르면 평가하지 않는다. 기기 종류를 보기 전에 같은 페이지와 IoU0.5 이상 위치를 최대 일대일 대응한다. 잘못 분류한 기기를 정답 종류와 다르다는 이유로 매칭에서 사라지게 하지 않는다.

주요 출력:

- 기기표 정밀도: 올바른 사용 가능 항목 / 사용 가능 항목.
- 기기표 유효 처리 범위: 올바른 사용 가능 항목 / 제공된 전체 정답 항목.
- 자동 분류 정밀도와 전체 정답 대비 유효 자동처리 범위.
- 실제 검출·누락·추가 검출·잘못된 분류 수, 검출 항목 중 검토 비율.

미검출 정답도 분모에 남는다. 분모0은null이며100%로 만들지 않는다. 중복 ID, 잘못된 라벨 좌표, 문서 불일치, 사례당1,000개 또는 후보 대응50,000개 초과는 명시 오류다. 서로 겹치는 복잡한 정답 객체의 정확한 대응은 위치 기반 평가의 한계이며, 정답 라벨의 정의와 사례 분할을 확인해야 한다.

평가 결과는 엔진의 production fingerprint, 소스 revision, 사전 해시, 그래프 버전, 기하·분류·기기표·평가기 정책과 예측/라벨 해시에 결박한다. 공급자 정답 확률이나 새 verified95 배지를 만들지 않는다. 기존 엄격 평가·외부 서명 정책을 낮추지 않는다.

## 검사 조건과 관측의 구분

별도로 선언한 합성 사례에는 정답4개, 검출3개, 누락1개를 넣는다. 기존 판독1개와 자동 분류1개를 갖는 경우 기기표 사용 가능2개가 되어도 유효 처리 범위는2/4여야 한다. 자동 분류를 제거한 대조 조건은1/4다. 잘못된 종류·중복 검출·빈 입력·손상된 좌표를 넣어 평가기의 반대 조건을 검사한다. 이는 고객 도면 정확도나 실제 검토시간을 실측한 자료가 아니다.

또 실제 DXF 파서에 분할된 LINE을 넣어 기존 회사 사전·반복 문맥으로 종류가 분류되는지 확인한다. 원래 type와 정격은 그대로 남아야 한다. 원본 descriptor와 fp2는 달라도 비교용 정규화는 같아야 한다.

브라우저 흐름은 PC1440px/모바일390px에서 기기표·CSV·원본·분류 수정 실패와 재시도·수정 후 재집계를 확인한다. HTTP 응답은 합성이고 파서·adapter·정정·기기표는 실제 함수를 사용한다. URL·제목·본문·수평 넘침·페이지 오류를 확인하며 화면을 보존한다. Browser plugin이 제공되지 않아 Playwright를 사용한다. 로컬 실행 도구는 TransportTimeoutError로 사용할 수 없었으므로 GitHub Actions의 실제 checkout에서 검사한다. 수동 육안 검사를 하지 않은 화면을 디자인 전수 확인으로 보고하지 않는다.

최종 실행 ID와 결과 수치는 PR의 원래 CI 및 artifact를 따른다. 소스 수정 없이 검사하며 실패와 수정 전후를 구분한다. 단계 미실행은 통과로 보고하지 않는다.
