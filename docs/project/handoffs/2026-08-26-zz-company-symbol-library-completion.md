# 회사별 심볼 사전 앱 저장 완료 인수인계

## 결론

기존의 수동 JSON 생성·재첨부 수준을 앱 안의 회사별 저장·선택·재사용 흐름으로 닫았다. 사용자가 DXF 분석 결과의 미인식 블록을 실제 기기 종류로 확정하면 현재 브라우저에 회사 사전으로 누적되고, 같은 도면 재분석과 다음 DXF의 빠른 분석·V3 전체 판독·정밀 검증에 같은 검증본이 적용된다.

## 변경

- 회사별 다중 사전, 활성 회사, JSON 반입·반출·삭제를 브라우저 로컬 저장소에 연결했다.
- 미인식 블록의 이름·기하 지문·수량을 화면에 표시하고, 사용자가 아는 항목만 기기 종류로 저장한 뒤 현재 DXF를 즉시 재분석한다.
- 블록 내부 선·곡선·중첩 기하를 정규화한 `fp2` 지문을 사용하며, 같은 지문 또는 같은 블록명에 서로 다른 기기 종류가 충돌하면 해당 키의 자동 판정을 중단한다.
- `/api/dxf`, `/api/drawing-jobs`와 재개 경로, `/api/team-review`가 동일한 활성 사전을 받도록 생산 호출 사슬을 연결했다.
- 회사당 1MB·전체 4MB UTF-8 한도와 공용 계약을 저장·읽기 양쪽에서 다시 검증한다.
- 저장 catalog 일부가 손상돼도 정상 회사를 빈 값으로 오인해 새 저장으로 덮지 않는다. 선택·가져오기·신규 등록을 모두 차단하고, 사용자가 원본 백업 다운로드를 시작한 뒤에만 저장 키를 초기화한다. 백업 생성기가 실패하면 원문은 그대로 남는다.

## 이유

기존 구현은 사용자가 생성된 JSON을 직접 보관하고 분석마다 다시 넣어야 해 “회사마다 다른 심볼을 앱이 기억한다”는 흐름이 아니었다. 또한 초기 브라우저 저장 구현은 catalog 일부가 손상되면 빈 저장소로 보인 상태에서 새 회사 저장이 원문 전체를 덮을 수 있었고, 첫 복구안도 다운로드 시작 전에 원문을 삭제했다. 사용자 입력을 축적하면서도 손상 시 기존 지식을 잃지 않는 실패 폐쇄 계약이 필요했다.

## 사용자 소유 변경

회사 도면, API 키, 계정 토큰과 로컬 평가 영수증은 읽거나 커밋하지 않았다. 검증 입력은 저장소의 공개·합성 DXF와 테스트 안에서 생성한 비민감 심볼을 사용했다.

## 완료

- 회사 선택→미인식 분류→저장→즉시 재분석→새로고침 복원→내보내기·삭제·가져오기→다음 DXF 자동 적용이 앱 화면에서 왕복한다.
- 활성 사전은 빠른 DXF, V3 최초 실행·PARTIAL 재개, 계통도 정밀 검증에 동일하게 전달된다.
- 손상·변조·과대 저장값, 모호한 지문·별칭, 별칭 없는 `fp1`은 자동 판정하지 않는다.
- 제품 코드 기준선은 기능 커밋 `b5bdfe98db4e0a075d2f01c59eb1fe012e943b32`와 데이터 무결성 후속 수리 `0a7d7dbda45a3d67ed3df095b8d122ef11665da1`이다.

## 부분 완료

회사 사전은 DXF `INSERT`와 블록 정의에 적용한다. 이미지·래스터 PDF의 픽셀 심볼 학습, 계정·서버 동기화, 여러 브라우저의 자동 병합은 포함하지 않는다. 다른 PC로 옮길 때는 JSON 반입·반출을 사용한다.

## 미검증

- 실제 고객사 DXF 묶음의 회사별 지문 충돌률·별칭 오분류율·미식별 회수율.
- 브라우저 프로세스를 완전히 종료한 뒤 프로필별 복원과 관리형 브라우저의 다운로드 차단 정책.

## 보류

기능 수리 자체의 잔여 보류는 없다. 실제 회사별 일반화 수치는 비기밀 공개 DXF corpus와 독립 라벨이 준비될 때까지 주장하지 않는다.

## 검증

- 문서 79개 링크·색인, TypeScript, 전체 ESLint 무경고, Next.js production build 66페이지가 통과했다.
- 전체 Jest는 349 suites·4,268 tests 통과, 의도된 2 suites·4 tests만 제외됐다.
- production 서버를 기동한 PDF 실경로 게이트는 17/17 통과했다.
- 회사 심볼 Playwright 3/3에서 정상 저장·재사용, 손상 원본 백업 후 초기화, 백업 생성 실패 시 원문 보존을 확인했다.
- 독립 검토는 손상 catalog의 save/import/upsert/select/delete가 모두 쓰기를 차단하고 원문을 보존함을 소스 probe로 확인했다. 백업 writer 실패와 성공 순서도 별도 probe로 재검증했으며 신규 BLOCKER/HIGH/P2는 없었다.
- 통합 게이트 첫 실행의 PDF 단계는 서버 미기동으로 exit 2였고, 같은 빌드 서버를 3010 포트에 기동한 뒤 17/17을 다시 통과시켰다.

## 다음 첫 행동

회사 기밀이 아닌 공개 DXF를 작도 관례·복잡도별로 묶고 독립 기기 라벨을 붙여, `fp2` 지문 충돌·별칭 오분류·미식별 회수율을 측정한다.
