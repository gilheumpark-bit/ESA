# 2026-09-09 미판독 계약 설계 검토와 적용

## 출발점과 설계 결정

검토 기준은 PR #71의 `d0b0bec9f871a6d82da70775e125b415d3169a89`다. 목적은 판독 가능한 정보를 궁극적으로 모두 읽되, 현재 확정할 수 없는 정보를 숨기거나 그럴듯한 값으로 바꾸지 않는 것이다. 70/30은 제품 방향을 설명한 예시이지 이 버전의 측정 정답률이 아니다. 이전 대화의 80% 완성도나 9/10 점수도 출고 판정에 사용하지 않는다.

기존 V3 `confirmed / ambiguous / unread`를 공통 타입으로 유지한다. 새 대문자 상태와 거대한 단일 객체를 도입해 기존 저장·API 소비자를 깨뜨리는 대신, 빠른 응답에 버전이 있는 `readout`을 추가한다. 값과 불확실성은 별개이며 타입을 확인했다고 전압·정격·결선도 확인된 것은 아니다.

| 검토 항목 | 결정과 이유 |
|---|---|
| 빠른 결과를 확정으로 간주할 근거 | 전체 confidence만으로는 개별 필드의 근거가 아니다. 현재 빠른 추출값은 검토 후보, 빠진 값은 미판독이다. V3의 기존 개별 근거 판정과 수량은 보존한다. |
| 낯선 심볼 | 위치가 유효하면 unknown과 원래 후보를 남긴다. 버리거나 load로 바꾸지 않는다. 위치가 잘못된 데이터까지 임의 좌표를 만들어 수용하지 않는다. |
| 계약 호환 | 빠른 SLD/DXF/PDF API의 기존 data·calcChain 필드는 유지하고 readout을 추가한다. 프런트는 동일한 순수 함수로 옛 응답에도 상태를 표시한다. 이는 빠른/V3 작업 API 자체의 통합이 아니다. |
| 측정 분모 | 검출된 기기·선·문자·결선·페이지 관계·정격별 상태만 집계한다. 검출하지 못한 대상 수는 알 수 없고 범주도 겹치므로 정답률·자동화율이나 합산 비율을 만들지 않는다. |
| 사람 수정 | 현재 반영된 종류·문자 정정 수를 별도로 표시한다. 과거 수정 횟수나 사람의 확정을 AI 자동화 증가로 세지 않는다. goldenEligible:false와 승인 전 자동학습 금지는 유지한다. |
| 계산 | 도면 일괄 실행은 명시된 입력만 사용한다. 가정·기본값은 자동 보충하지 않는다. 검토 동의가 UNKNOWN을 CONFIRMED로 바꾸지는 않으며, 누락은 해당 단계와 의존 단계만 보류한다. |
| 상태 요약 | 저장 카운터를 하나 더 만들지 않고 현재 문서에서 도출한다. 화면·CSV·인쇄가 동일한 요약 함수를 사용한다. |

## 재현한 결함과 수리

1. count-register가 unread 노드를 확정/모호 어느 쪽에도 세지 않아 미판독만 있는 기기를 0대·COMPLETE로 만들 수 있었다. unread 수를 보존하고 미판독만이면 실물 대수 null, 섞여 있으면 확인된 대수만 유지하면서 HOLD로 둔다. 페이지 간 hold도 완료 계수로 간주하지 않는다.
2. type/label/text 수정 시 대상의 모든 사유와 모든 LINE_CONTINUITY_UNCERTAIN을 제거하던 범위를 줄였다. 종류 수정은 해당 종류 미판독 사유만, 문자 수정은 해당 OCR 사유만 해제한다. 해상도·구획 누락·무관한 연결 이유는 남긴다. 재생성되는 unbound 식별자만 교체해 중복 누적을 막고 경계 연결 원장도 보존한다.
3. 종류 수정값 unknown/모름/미판독은 확정된 기기 종류가 아니다. 사용자가 미판독으로 되돌릴 수 있으며 관련 사유가 남는다. 이름표 수정만으로 미판독 종류를 확정하거나 지우지 않는다.
4. 보고서 verificationExtra가 계산된 claimsComplete·documentStatus·holdReasons를 덮을 수 있던 순서를 수정했다. 정격·페이지 간 관계·잔존 node holdCode도 전체 판독 완료 조건에서 빠뜨리지 않는다. 개별 정상 확정값을 함께 지우지는 않는다.
5. 빠른 이미지 파서가 미지원 종류를 버리고 DXF INSERT가 load로 대체하던 경로를 수정했다. 신뢰도 높은 unknown도 V3 기기 확정으로 올리지 않는다. unknown은 회사 사전의 승인된 기기 종류로 저장할 수 없다.
6. 빠른 계산 체인의 입력에 일반 계산기 기본값을 조용히 넣고 실패 선행 단계를 무시하던 동작을 수정했다. 원본에서 확인한 명시 입력만 요청하며 입력·요청은 분석 결과 버전에 묶는다. 입력 없는 부하 행은 목록에서 제거하지 않는다. 정격 용량을 개별 최대수요로 대체하던 제안도 입력을 비워 최대수요 확인을 요구한다.

그래프 조립 버전은 `evidence-graph-continuity-v9`로 갱신한다. 과거 저장 결과 전체를 자동 변환하거나 독립 실증을 다시 취득한 것은 아니다. 과거 수량 판정을 새 계약으로 재검증하려면 재분석이 필요하다.

## 검증 절차와 증거

단위 검사는 실제 production 함수에 대해 미판독 계수, 미확정 정격, metadata override, 수정 사유 보존, 경계 원장, unknown 재지정, 사람 확정 집계, CSV/인쇄, 빠른 필드 상태, 명시 입력·중첩 배열·기본값·누락 부하를 검사한다. 기존 테스트가 요구하던 ‘미지원 기기 삭제’ 계약은 위치·후보 보존으로 변경하되 잘못된 좌표·끊긴 참조·단위 없는 길이 거부는 유지한다.

로컬 Node22에서 기존 코드와 동일한 16개 핵심 조건을 비교했다. 수정 전 4통과/12실패, 수정 후 16/16이다. 테스트 파일의 나머지 4개 신규 출력 검사는 이 비교의 대상이 아니며 건너뜀으로 기록한다. 새 fixture와 상태 집계 helper는 양쪽에 동일하게 제공했고 비교 대상 count/report/correction 함수는 각 버전 그대로였다. 전체 독립 도면 정답률 비교가 아니다.

관련 로컬 검사 13개 suite/193개 테스트와 기존 정밀도·보고서 Node 계약 63개도 통과했다. Node22 전체 Jest 실행은 로컬 도구 제한시간 안에 끝나지 않아 전체 통과로 보고하지 않는다. 로컬 Chromium의 loopback 탐색은 관리자 정책으로 차단되어 화면 통과 증거가 아니다. Browser plugin이 없어 Playwright를 사용하며, 원격 Node24의 정확한 잠금파일과 production 서버에서 전체 검사를 다시 수행한다.

새 브라우저 시나리오는 PC1440px/모바일390px의 빠른 검토/미판독 표시, 방향 미판독, 원본 확인 전 실행 억제, 누락 입력/선행 계산 보류, 독립 명시 입력 실행, 분석 교체 시 확인 초기화, V3 사람 정정 후 다른 사유·CSV 보존을 다룬다. HTTP 입력은 명시적인 합성 fixture이고, 수정 응답은 실제 applyDrawingCorrection 함수를 통과한다. 운영 계정·서버 소유권 검증으로 확대 해석하지 않는다.

최종 코드 SHA와 원격 검사 결과는 PR #71의 해당 HEAD CI 및 검증 댓글을 따른다. 기존 녹색 실행을 새 변경의 증거로 사용하지 않으며, PDF gate와 브라우저 검사는 독립 서버를 사용한다.

## 적용 경계

추가 모델·해상도 축소·호출 예산 변경·판정 임계값 완화는 없다. 사람이 확인해야 하는 값이 있으면 계산기로 이동해 명시적으로 완성할 수 있다. 일괄 실행 확인 체크박스는 인증/기술 승인이나 영구 정답 라벨이 아니다.

회사 공용 사전 승인 서버·수정값 자동학습·독립 평가셋 발행·실제 AI 자동처리율 측정은 구현하지 않았다. 현재 회사 사전은 기존 브라우저/JSON 범위이고 정정 기록은 자동 학습하지 않는다. 기기 정격의 공간 귀속과 기존 정밀 판독 휴리스틱 전부의 정확성을 새로 인증한 것도 아니다.

빠른/V3 단일 작업 통합과 UIV-001 재계산 간헐 현상, 안전 상수 판본 부채는 OPEN을 유지한다. 이번 수정은 불확실성 정보를 덮거나 지우는 경로를 줄이는 것이며 ‘모름 허용만으로 안전 보장’이나 ‘현재 70% 정답’을 주장하지 않는다. main 병합·운영 배포·실제 회사 도면/비밀값 사용은 하지 않는다.
