# ESA 종합 감사 보고서 · 수리 설계도

2026-07-24 · 감사 기준선 `6bcf39f` (base `fef4352`) · PR [#24](https://github.com/gilheumpark-bit/ESA/pull/24)

CI 복구에서 시작해 전수 딥 패스까지 이어진 감사의 결론과, 확인된 결함을
닫기 위한 설계를 한 문서에 담는다. 토폴로지 재설계(§6.5)와 약점 축 90점 설계(§6.6)를 **본문에 그대로** 포함해
이 문서 하나로 감사와 설계가 모두 닫히게 했다. 이 둘은 다른 곳에 사본이 없다.

## 0. 이 문서를 읽는 법

- **주장에는 앵커가 있다.** 커밋 SHA, CI run/job ID, 파일:라인, 실행 명령.
  앵커 없는 문장은 추정이며 그렇게 표시했다.
- **실행하지 않은 검사는 통과로 쓰지 않는다.** 이 감사 세션은 `npm ci`가
  레지스트리 403으로 막혀 있어 `tsc`·`lint`·`jest`·`build`·`gate:pdf`를
  직접 실행하지 못했다. 해당 결과는 전부 CI 실측을 인용한다.
- **오탐을 결함과 같은 비중으로 기록한다.** 걷어낸 오탐이 이번 감사의
  최대 소득이다.

## 2. 확정 결함 (5건)

### [DB-001] 🟡 RLS가 앱 트래픽의 방어선이 아니다

- **근거**: 정책 70개가 `auth.uid()`(Supabase Auth 주체)에 의존.
  앱은 Firebase ID 토큰을 서버에서 검증하고 DB는 `service_role`로 접근하며,
  `service_role`은 RLS를 우회한다. 브라우저 Supabase 클라이언트 호출처 0.
- **현재 위험**: 없음. 실제 경계는 라우트 핸들러의 서버측 소유권 검증이며
  이번 감사에서 동작을 확인했다.
- **미래 위험**: 브라우저 클라이언트를 추가하면 Firebase 사용자에게
  `auth.uid()`가 NULL이라 모든 own-row 정책이 **조용히 전면 차단**된다.
  안전 방향이지만 원인 불명 장애가 된다.
- **수리**: 마이그레이션 헤더와 `SECURITY.md`에 "이 정책들은 service_role
  경계 하에서 비활성인 심층 방어이며, Firebase 주체를 RLS로 쓰려면
  `request.jwt.claims` 기반 재작성이 필요하다"를 명시.

### [DB-002] 🟡 `community_votes` 공개 SELECT가 `user_id`를 노출한다

- **근거**: `001_initial_schema.sql`의 `cv_select_all ... FOR SELECT USING (true)`.
  테이블에 `user_id` · `target_id` · `direction(-1/1)`이 있어 **누가 어떤 글에
  반대표를 던졌는지** 조회 가능.
- **현재 도달 경로 없음**: 브라우저 Supabase 클라이언트 호출처 0,
  `NEXT_PUBLIC_SUPABASE_ANON_KEY`는 `/api/health`(서버)와 테스트에서만 참조돼
  클라이언트 번들에 인라인되지 않는다. `supabase-runtime-contract.test.ts`가
  특정 경로의 anon 키 부재를 계약으로 검증하고 있다.
- **수리**: `004`가 `cq/ca_select_all`을 `hidden = false`로 교체한 선례를 따라
  집계 뷰 또는 본인 표 한정으로 축소.

### [LLM-001] 🟡 출처 탐지 창이 비대칭이다

- **근거**: `engine/llm/output-filter.ts:110-115`는 숫자에 대해
  `sPos >= pos && sPos <= pos + 200` — **전방 200자만**. 같은 파일 246-251의
  표준 인용 검사는 `Math.abs(sPos - pos) <= 150` — **양방향**.
- **결과**: `[SOURCE: KEC 232.52] 전압강하는 4.14V입니다` 순서면 정당한
  출처가 무시돼 `[BLOCKED: 출처 없는 수치]`로 치환된다. 정답을 훼손하는
  방향의 오차단이다.
- **미검출 이유**: `output-filter.test.ts`의 통과 케이스가 전부 소스 태그를
  숫자 **뒤에** 둔다. 앞에 두는 케이스가 없다.
- **수리**: 숫자 검사도 양방향으로 통일하고, 소스 태그 선행 케이스를
  회귀 테스트로 잠근다.

### [LLM-002] 🔵 `isClean()`이 `filterLLMOutput()`보다 엄격하다

- **근거**: `isClean()`은 `trustedInput` 인자가 없어 사용자 입력을 그대로
  인용한 숫자도 거부한다. `filterLLMOutput()`은 `isTrustedInput`으로 통과시킨다.
- **실피해 없음**: production 호출처 0 (`engine/index.ts` 재수출만).
- **수리**: 시그니처를 맞추거나, 사용처가 없으면 `DORMANT_MANIFEST` 등재.

### [LLM-003] 🔵 한국어 연도가 오차단될 수 있다

- **근거**: 단위 정규식이 `[A-Za-zΩ]+`라 `년`을 단위로 인식하지 못한다.
  `2021년 개정` 의 `2021`은 unit 없음 · 값 > 10 · 허용 문맥 아님 → 차단.
  `KEC 2021`처럼 표준명이 앞서면 허용 문맥에 걸려 통과한다.
- **수리**: 허용 단위에 한국어 시간·수량 단위(`년 월 일 개 명 회 배`)를 추가.

## 3. 오탐 6건 — 결함이 아니었던 것

grep 신호만으로 보고했다면 전부 거짓 결함이 됐을 항목이다. 같은 실수를
반복하지 않도록 판정 근거를 남긴다.

| 오탐 후보 | 기각 근거 |
|---|---|
| UPDATE 정책 `WITH CHECK` 누락 6건 | PostgreSQL은 `WITH CHECK` 생략 시 `USING` 식을 새 행에도 적용한다. 소유자 변경은 이미 차단됨 |
| `target="_blank"` rel 누락 3건 | `rel="noopener noreferrer"`가 다음 줄에 있음. 동일 행 grep의 한계 |
| `dangerouslySetInnerHTML` 2건 | `LaTeX.tsx`는 KaTeX 출력이며 **`trust: false`** 설정됨. `ThemeInitScript.tsx`는 사용자 입력이 닿지 않는 정적 상수 |
| 계산기 테스트 단언 부족 5파일 | `close()` 헬퍼가 `expect`를 래핑. 리터럴 `expect(` 카운트의 한계 |
| `/mobile` 로딩 UI 없음 | `'idle'\|'capturing'\|'processing'\|'done'\|'error'` 상태 기계 사용 |
| BYOK `localStorage` 평문 저장 | 저장값은 `encryptKey()` 산출 암호문(`v5:` 접두). 키는 IndexedDB 비추출 CryptoKey. CLAUDE.md 계약 준수 |

### 6.2 P0 수리 명세

**R1 — 출처 창 양방향화** (`engine/llm/output-filter.ts`)

```
현재: sPos >= pos && sPos <= pos + 200        (전방 한정)
수리: Math.abs(sPos - pos) <= 200             (표준 인용 검사와 동일 형태)
```
회귀 잠금: 소스 태그가 숫자 **앞**에 오는 케이스 · 뒤에 오는 기존 케이스
둘 다 통과. 차단 강도는 그대로 유지된다(창이 넓어질 뿐 무출처 숫자는 계속 차단).

**R2 — RLS 비활성 사실 명시** — 문서만. `002_firebase_contract.sql` 헤더와
`SECURITY.md`에 service_role 경계와 `auth.uid()` 비활성을 기록.

**R3 — `cv_select_all` 축소** — 새 마이그레이션(`006_`)으로
`DROP POLICY` → 집계 뷰 또는 본인 표 한정 정책 생성. `004`의 형태를 따른다.
**주의**: 접두사 중복(`001_` 2건)이 이미 있으므로 새 파일은 `006_`부터.

**R4 — `npm audit` high 1건** — 어떤 패키지인지 먼저 식별해야 한다(현재는
CI 설치 로그의 요약만 확인). CI에 `npm audit --audit-level=high` 단계 추가.

**R5 — `api-logger` 전면 배선** — 현재 5/49. 라우트 핸들러 공통 래퍼로
일괄 적용하되, BYOK·비밀값이 로그에 들어가지 않도록 마스킹 계약을 함께 건다.

**R6 — `coverageThreshold`** — 현재 커버리지를 먼저 측정해 그 값을 기준선으로
고정한다(임의의 높은 수치를 걸어 게이트를 깨뜨리지 않는다).

**R7 — 한국어 단위** — 허용 단위 정규식에 `년 월 일 개 명 회 배 시간 분` 추가.

### 6.3 P1 — M0가 잠금 해제 지점

`gate:pdf` 6/17은 **원인 미확정이 아니다**. 전후 차분으로 롤백 대상이
없음을 확정했다(선분 추출 로직·`endpoint-snap.ts`·fixture·기대값·pdfjs 버전
전부 무변경). 남은 분기는 하나 — 게이트 fixture와 파이프라인 계약 중
어느 쪽이 틀렸는가.

```bash
npm ci && npm run build && npm start -- --port 3010 &
npm run gate:pdf -- http://127.0.0.1:3010
# circuit.pdf(4pt 간격 평행 수직선 2개)와 grid.pdf(닫힌 사각형)의
# lines.length · snap.stats 대조
```

이 실측이 S1(스냅 반경, §6.5)의 첫 데이터도 된다 — `circuit`은 반경 계산이
결과를 지배하는 형태다.

### 6.4 P2 — 사람 시간이 드는 구간

W1 라벨 공장의 전문은 §6.6에 있다. 핵심 제약 둘을 여기 먼저 적는다.

- **순환성**: pre-label을 만드는 파이프라인과 평가받는 파이프라인이 같다.
  15장 중 2장 백지 홀드아웃으로 앵커링 편향을 수치 추정해 지표 옆에 병기하며,
  편향 추정 없는 F1은 출고하지 않는다.
- **조달**: 재배포 가능한 실도면 13장 추가 확보가 실제 임계 경로다.
  부족분은 저장소 밖 비공개 세트 + SHA-256 앵커로 운영한다.

### 6.5 토폴로지 스냅 반경·기기 분류 재설계 (S1·S2·S3)

알고리즘 정밀 리뷰에서 확인된 3건을 수리하기 위한 설계다. 판정 입력을 바꾸는
변경이므로, 어느 것도 실측 없이 착지하지 않는다.

#### 근거 (전부 저장소 안에서 재확인 가능)

**G1 — 스냅 허용반경이 도면 외곽 크기에 비례한다.**
`engine/topology/endpoint-snap.ts`의 `defaultTolerance`는 `bbox 대각선 × 5%`다.
축척 불변성은 얻었지만(정수 격자 시절 L3-02 미터 단위 도면에서 재현율 0% 회귀의
수리 결과), 반경이 도면 크기에 비례해 커진다. 허용반경보다 짧은 선분은 양끝이
같은 노드로 붕괴해 자기루프로 폐기된다. 체크인된 실도면 출력의 실측:

| 도면 (`fixtures/drawings/realworld/results/`) | 선분 | 결선 | 자기루프 폐기 | 폐기율 |
|---|---:|---:|---:|---:|
| kimm-p14-mid | 498 | 120 | 129 | **25.9%** |
| kimm-p40-basic | 556 | 170 | 118 | **21.2%** |
| kimm-p5-advanced | 1,987 | 314 | 199 | 10.0% |
| kimm-p9-table-adversarial | 588 | 306 | 54 | 9.2% |
| rsc-p4-basic-en | 149 | 73 | 14 | 9.4% |

폐기된 선분에는 치수선 같은 정당한 폐기도 섞여 있으므로 폐기율 자체가 오류율은
아니다. 그러나 심볼 리드선·짧은 연결 스텁이 이 경로로 사라질 수 있고, 상류에서
사라진 결선은 하류의 어떤 교차검증도 복구하지 못한다.

**G2 — 기기 분류가 앵커 없는 부분 문자열 매칭이다.**
`agent/drawing/recommendation-engine.ts`의 `isProtection` 등:
`/breaker|vcb|acb|mccb|fuse|cb|rcd/.test(t)`. `cb`·`gen`·`bar`가 임의 문자열
내부에서 걸린다. 이 분류가 `severity: 'critical'` 소견("보호기 미확인")의
입력이다.

**G3 — 경로 탐색이 경로 배열 복사 BFS를 source×load 쌍마다 재실행한다.**
`findPath`가 큐에 경로 배열을 통째로 복사해 쌓고, 전원×부하 조합마다 그래프를
다시 탐색한다. 행동은 옳고 비용만 불필요하다.

#### 설계

##### S1 — 스냅 허용반경: 도면 자신의 선분 통계에서 유도

**요구 불변식**
1. 축척 불변 — L3-02 미터 단위 fixture 100% 유지 (이걸 깨면 과거 회귀의 재발)
2. 도면 외곽 크기 독립 — 큰 도면에서 반경이 절대값으로 커지지 않는다
3. 결정론 — 같은 입력이면 같은 반경
4. 퇴화 안전 — 어떤 단위계에서도 반경 0 금지

**유도식 (후보 — 2026-07-24 적대 점검으로 개정)**

```
tolerance = clamp( α × P10(선분 길이 분포),
                   하한 = bboxDiag × 0.005,
                   상한 = bboxDiag × 0.05 )
```

- 자기루프 붕괴 조건은 `tolerance ≥ 선분 길이`다. `α × P10`을 걸면 길이 하위
  10% 밖의 모든 선분은 구조적으로 붕괴가 불가능해진다.
- 상한 = 현행식이므로 **반경은 현행보다 커질 수 없다** — "더 붙는" 방향의
  회귀는 구조적으로 배제된다.
- **하한이 필요한 이유(초판 누락)**: P10 풀은 `minLineLength`(10pt) 통과
  선분이지만, 접지 기호·해칭·화살촉 같은 짧은 장식 선분이 다수인 도면에서는
  P10 자체가 무너져 반경이 0에 수렴한다 — 아무것도 안 붙어 결선 재현율이
  붕괴하는, 현행과 정반대의 실패다. 초판은 "너무 큰" 방향만 보고 "너무 작은"
  방향을 보지 않았다. 하한 0.5%는 이 붕괴만 막는 안전판이며 크기 의존성은
  하한에서만 재도입된다.
- 후보 α ∈ {0.5, 1.0}, 대조군은 현행식. 선분이 3개 미만이면 P10이 무의미하므로
  현행식으로 폴백한다.

**과소 병합만 위험이 아니다(초판 누락) — 오병합이 더 위험하다.**
서로 다른 두 노드가 한 노드로 합쳐지면 거짓 결선이 생기고, 이는 "보호기
없음" critical 소견을 **거짓으로 소거**하는 방향으로 작용할 수 있다(없는
경로에 보호기가 있는 것처럼 보임). 따라서 결정 규칙은 재현율만이 아니라
**엣지 정밀도(precision)** 를 독립 항목으로 본다 — evaluator의 edgeF1은 둘을
합산하므로 F1 뒤에 정밀도 하락이 숨지 않게 P/R을 분리 보고한다.

**앵커 우선 규칙의 결함(초판 누락).** 현행 `resolve()`는 반경 내 앵커가
있으면 **거리 무관하게 앵커가 접점을 이긴다** — 끝점이 다른 선 끝점과 1pt,
기기 앵커와 9pt 떨어져 있어도 앵커로 스냅된다. 배선 접점이 기기 근처를
지나는 도면에서 접점이 기기로 흡수돼 토폴로지가 왜곡된다. S1에 포함한다:
후보 집합(앵커 ∪ 기존 접점)에서 **최근접이 이긴다**. 이 변경도 동일한 결정
규칙의 심판을 받는다.

**결정론의 조건(초판 미명시).** 접점 군집화는 선착순 흡수라 입력 순서에
민감하다(A–B 근접, B–C 근접, A–C 원거리일 때 순서가 군집을 결정). 파서
출력 순서가 고정이므로 현재는 결정론이 성립하지만, 이는 **순서 안정성에
기대는 결정론**이다. 스냅 입력을 좌표 사전순으로 정렬한 뒤 군집화해 순서
의존을 제거한다 — 이러면 병렬화·소스 교체에도 결과가 불변이다.

**결정 규칙 (실측으로 채택, 취향 금지)**

후보별로 전부 측정해 우세 후보를 채택한다:
- (a) 합성 15장 라벨 재현율 (`fixtures/drawings/synthetic`) — 100% 유지 필수
- (b) 실도면 5장 블라인드 라벨 relations 대조 (3차 실증 교보재) — **정밀도·재현율 분리 보고**, 어느 쪽도 하락 금지
- (c) 실도면 자기루프 폐기율 — 유의미한 감소가 채택 근거
- (d) `gate:pdf` 17건 — 전 항목
- (e) `test:region-continuity` — 구획 경계 합치기(`Pxx-Cxxx`)는 자체 허용반경을 쓰지만 스냅 결과를 입력으로 받으므로 회귀 심판에 포함한다(초판 누락)
- 동률이면 폐기율이 낮은 쪽.

**감사 가능성**: 선택된 반경과 유도 근거(어느 팔이 이겼는지, P10 값)를
`snap.stats`에 기록해 `rawDescription` 영수증으로 남긴다. 반경이 왜 그 값인지
사후에 재구성할 수 있어야 한다.

##### S2 — 기기 분류: 1회 정규화 어휘 계층

판정 지점마다 정규식을 돌리는 대신, 그래프 구축 시 한 번 정규화한다.

```
deviceClass: 'source' | 'protection' | 'transformer' | 'load' | 'bus' | 'unknown'
```

- **라틴 코드와 한국어 어휘는 매칭 규칙이 다르다(초판 미분화).**
  - 라틴 약호(`vcb`·`acb`·`mccb`·`elb`·`nfb`·`rcd`·`fuse`·`cb`)는 짧아서
    오탐 위험이 크므로 **토큰 전체 일치**만 인정한다. `cb`는 독립 토큰일
    때만 protection이다.
  - 한국어 기기어(`차단기`·`변압기`·`발전기`·`전동기`·`모선`)는 공백 없는
    복합어로 나타난다(실례: "주차단기", "모선 (부스바)"). 토큰 경계를
    요구하면 전부 놓친다. 이쪽은 **선별된 장어휘의 부분 문자열 일치**를
    허용한다 — 3음절 이상 기기어는 우연 오탐 확률이 라틴 2자 약호와 다르다.
    허용 목록은 열거형으로 잠그고 항목별 반증 테스트를 붙인다.
- **분류 입력의 우선순위를 명시한다(초판 누락)**: `confirmedType` →
  `rawLabel` → `typeCandidates[0]` 순으로 시도하되, 어느 필드가 분류를
  만들었는지 `classProvenance`로 기록한다. `typeCandidates[0]` 유래 분류는
  추측이므로 SUPPORTED 승격 불가 규칙(기존 `hasConfirmedType` 계약)이 그대로
  적용된다.
- **unknown은 unknown으로 남긴다.** `recommendation-engine`의
  `hasConfirmedType` HOLD 계약(2026-07-24 수리)과 합성되어, 미확정 종류는
  SUPPORTED 소견을 만들지 못한다.
- 별칭 표는 반증 테스트로 잠근다 — 부분 문자열 오탐 케이스(예: 토큰 내부의
  `cb`·`bar`)가 unknown으로 남는 것을 명시적으로 검증.
- 마이그레이션: `isSource`/`isLoad`/`isProtection`/`isBusLike`를 deviceClass
  조회로 교체. 분류 결과가 바뀌는 기호가 있는지 실도면 결과로 전후 대조한다.

##### S3 — 성능: 조건부 착수

- **S3a `findPath` (즉시 가능, 행동 동일)**: 경로 배열 복사 대신 parent-map
  BFS. source당 1회 탐색으로 모든 load 도달·경로를 얻는다. 판정 결과 불변,
  비용만 감소. 전체 Jest green이 착지 조건.
- **S3b 공간 인덱스 (보류)**: `resolve()`의 앵커·접점 선형 스캔을 격자 해시
  (셀 크기 = tolerance)로 교체. 현 규모(페이지당 ≤2k 선분)에서는 병목이
  아니므로 **페이지당 선분 10k 초과 또는 프로파일 실측에서 스냅이 상위 병목일
  때** 착수한다. 그 전에는 하지 않는다 — 측정 없는 최적화는 이 저장소의
  원칙 위반이다.

#### 착수 순서와 게이트

```
M0  gate:pdf 실측 (PROJECT_STATE '다음 첫 행동 0')
     circuit vs grid의 lines.length·snap.stats 대조
     → 파서와 게이트 기대값 중 틀린 쪽 확정
S1  후보 반경 실측 → 결정 규칙으로 채택 → 착지     (M0 이후)
S2  어휘 계층 + 반증 테스트 → 전후 대조 → 착지      (M0와 독립, 전체 Jest 필수)
S3a findPath parent-map                              (즉시 가능)
S3b 격자 해시                                        (조건 충족 시까지 보류)
```

M0·S1이 같은 지점(스냅 반경이 지배하는 fixture)을 가리킬 가능성이 높다 —
`gate:pdf`에서 실패하는 `circuit`은 4pt 간격 평행 수직선 2개로, 반경 계산이
결과를 지배하는 형태다. M0 실측이 S1의 첫 데이터가 된다.

#### 비변경

- `gate:pdf` R1~R15 기대값 — 실행 없이 기대값을 낮추는 것은 게이트 약화다.
- HOLD/SUPPORTED/BLOCK 의미론과 판정 계층 계약.
- 합성·실도면 교보재와 블라인드 라벨 — 이 설계의 심판이지 수정 대상이 아니다.

### 6.6 약점 축 90점 설계 (W1·W2·W3)

도면 시스템 채점(2026-07-24)에서 약점으로 확인된 세 축을 90 이상으로 올리는
설계다. 현재: 정확도 계량 35 · 게이트 안정성 55 · 재현성 60.

#### 채점의 정의부터

**계량 축의 점수는 측정값의 크기가 아니라 측정의 존재와 신뢰성이다.**
15장을 측정해 edgeF1이 0.80이 나와도 계량 축은 90이 될 수 있다 — 신뢰할 수
있는 숫자가 존재하고 제품 주장이 그 숫자에 결박되기 때문이다. 그 경우
`verified95=false`가 유지되는 것이 정확히 옳은 동작이다. 점수를 올리기 위해
임계값을 낮추거나 라벨을 관대하게 만드는 것은 이 설계의 실패 조건이다.

#### W1 — 정확도 계량 35 → 90: 라벨 공장

병목은 알고리즘이 아니라 **평가기가 요구하는 형태(공간 bounds 포함)의 실도면
정답이 0장**이라는 것이다. 전문가가 백지에서 라벨을 만들면 도면당 수 시간이
든다. 설계의 핵심은 **제품이 이미 가진 교정 인프라를 라벨 공장으로 재사용**해
전문가 시간을 교정·판정에만 쓰게 하는 것이다.

##### 공장 파이프라인 (기존 인프라 재사용)

```
① pre-label   파이프라인 실행 → 기호·결선·문자 초안 (자동, 0 전문가시간)
② 블라인드 교정  이종 모델 2좌석이 상호 무인지로 초안을 교정
               — /api/drawing-jobs/[id]/corrections 로 수행:
               CAS 버전·요청 고유키·전후 재계산 영수증이 그대로 증명이 된다
③ 함정 검증    라벨에 심은 trap(기존 p14 라벨의 trap 관행)을 좌석이
               적발했는지 채점 — 기준 미달 좌석의 교정 전체 기각
④ 판정        두 좌석 불일치 항목 + humanReviewQueue 를 인간 도메인
               전문가가 판정, 표본 ≥20% 스팟체크
⑤ 출고        adjudicated label + SHA-256 + 교정 영수증 체인 첨부
```

②의 요점: pre-label 교정 방식은 앵커링 편향이 있다. 그래서 (a) 이종 모델
2좌석 상호 무인지, (b) trap 경계(③), (c) 인간 판정(④) 세 겹으로 상쇄한다.
trap은 "초안이 맞는 것을 틀렸다고 하는지"가 아니라 **"초안이 틀린 것을
그대로 통과시키는지"** 를 잡는 장치다.

**순환성 — 이 설계의 가장 큰 구조적 위험(적대 점검으로 추가).**
pre-label을 만드는 파이프라인과 라벨로 평가받는 파이프라인이 같다. 파이프라인이
**체계적으로** 틀리는 항목은 두 좌석의 교정도 통과할 수 있고(둘 다 같은 초안을
보고 있으므로), 그 오류가 정답에 박제되면 측정 F1이 과대평가된다 — trap은
심어둔 오류만 잡지, 파이프라인의 자연 발생 오류가 박제되는 것은 못 잡는다.
완화 두 겹을 의무화한다:
- **백지 홀드아웃**: 15장 중 2장은 pre-label 없이 백지에서 라벨링한다.
  같은 도면의 교정식 라벨과 대조해 **앵커링 편향을 수치로 추정**하고, 그
  추정치를 최종 보고서에 지표 옆에 병기한다. 편향 추정 없는 F1은 출고하지
  않는다.
- **trap 회계**: trap은 심을 때 별도 대장에 기록하고 **출고 라벨에서 전량
  제거**를 대장 대조로 검증한다. trap이 정답에 새면 그 자체가 정답 오염이다.
  도면당 trap ≥5개 — 3개 이하로는 좌석 경계 판정(적발률 기준) 자체가
  통계적으로 무의미하다.

##### 독립성 사다리

| 등급 | 정의 | 현재 |
|---|---|---|
| IND-1 | 동일 모델 2좌석 블라인드 | p14 라벨이 여기 |
| IND-2 | **이종 모델** 2좌석 + trap 적발 기준 통과 | 공장 기본 출고 등급 |
| IND-3 | 인간 도메인 전문가가 불일치·humanReviewQueue 판정 + ≥20% 스팟체크 | claim 자격 등급 |

##### 표본 크기 — 도면 수가 아니라 항목 수가 목표다

임계값 0.95를 신뢰구간 반폭 0.01로 말하려면 (정규근사, 실게이트는 Wilson):

```
n ≥ 1.96² × 0.95×0.05 / 0.01²  ≈ 1,825 (엣지·기호)
n ≥ 1.96² × 0.98×0.02 / 0.01²  ≈   753 (접점, 임계 0.98)
```

체크인된 실도면 실측 수율이 도면당 엣지 73~314·접점 36~54이므로:

- **목표: 실도면 15장** — 엣지 ≥1,800 · 기호 ≥1,500 · 접점 ≥700
- 층화: 난이도(초/중/고) × 유형(SLD·패널 스케줄·배치) 각 칸 최소 3장
- 항목은 도면 안에서 군집이므로(iid 아님) 위 n 계산의 정규근사는 **낙관**이다.
  실제 신뢰구간은 도면 단위 클러스터 부트스트랩으로 산출하고(설계효과 감안 시
  유효 표본이 절반까지 줄 수 있다), 보조 지표로 **도면별 최저값**을 함께
  보고한다 — 평균이 좋은데 특정 도면 유형이 무너지는 것을 숨기지 않는다.

**15장은 어디서 오는가(적대 점검으로 추가 — 초판이 조달을 침묵했다).**
이 저장소는 공개 저장소다. 라벨 교보재로 체크인하려면 도면이
**재배포 가능**해야 하고, CLAUDE.md는 회사 원본 유입을 금지한다. 현재 확보분은
공개 출처 2건(kimm·rsc)뿐이며, 재배포 가능한 한국 전기도면 13장이 추가로
존재한다는 보장이 없다 — **이 조달이 15장 계획의 실제 임계 경로다.**
- 우선: 공공기관 발주 공개 설계도서(조달청·나라장터 첨부), 대학·연구기관
  공개 자료 등 출처·라이선스를 `SOURCES.md`에 기록할 수 있는 것만.
- 조달이 15장에 못 미치면: 부족분은 **비공개 라벨 세트**로 운영한다 — 도면과
  라벨은 저장소 밖에 두고, 저장소에는 SHA-256 앵커와 평가 영수증만 남긴다.
  fail-closed 게이트는 해시 대조로 동작하므로 이 구조를 이미 지원한다.
  이 경우 외부 재현성은 공개분으로 한정된다는 사실을 보고서에 명시한다.

##### claim 자격 술어 (manifest에서 기계 판정)

`claimEligible=true`는 다음 전부가 참일 때만:

```
strata 충족(3×3 각 칸 ≥3장) ∧ n 충족(위 표) ∧ independence ≥ IND-3
∧ 동일 데이터셋 3회 반복 영수증 ∧ Ed25519 attestation 서명
∧ evaluatorVersion 고정 ∧ 예측 해시 일치
```

전부 기존 부품이다 — fail-closed 게이트(`gate:sld-golden`)·서명 검증·반복
영수증(`runBenchmarkSuite`)은 이미 구현돼 있고, 지금은 넣을 데이터가 없어
의도대로 exit 1일 뿐이다.

##### 공급자 매트릭스

`runBenchmarkSuite` × {OpenAI, Gemini, Claude} × 3회 반복. 지표 평균·분산,
도면당 비용, 타임아웃·누락률을 같은 15장에서 기록한다. PROJECT_STATE
'다음 첫 행동 2'와 동일 항목 — 이 설계가 그 실행 계획이다.

적대 점검 보강 2건: **(1) 평가 대상 예측은 공급자·모델 ID·온도까지 고정해
영수증에 박는다** — VLM은 비결정적이므로 "어느 실행이 채점당했는가"가
모호하면 3회 반복의 분산 보고가 무의미해진다. **(2) API 비용을 예산으로
명시한다**: 도면당 Vision 호출 예산(현행 기본 110콜/페이지)을 감안하면
15장 × 3공급자 × 3회는 유의미한 비용이다 — 사전 추정치를 산출하고 예산
승인 없이 매트릭스를 시작하지 않는다. 전문가 시간만 비용이 아니다.

##### 비용 (정직하게)

전문가 시간: 교정 검토 도면당 1~2시간 + 판정/스팟체크 → **15장에 약 3~4
전문가·일**. 백지 라벨링(도면당 수 시간 × 15장) 대비 약 1/3. 이 시간은
설계로 제거할 수 없다 — 제거하면 IND-3이 무너지고 지금의 IND-1 한계를
재생산한다.

#### W2 — 게이트 안정성 55 → 90

1. **M0 실측**으로 `gate:pdf` 6/17의 틀린 쪽(파서 vs fixture)을 확정하고 수리.
2. **실도면 유래 스트로크 재생 fixture 추가** — M0의 남은 가설이 "게이트
   fixture가 실도면을 대표하지 못한다"이므로, 자체 확보 공개 도면(kimm)의
   스트로크 좌표 서브셋(~50선)을 content stream으로 재생하는 R-real 케이스를
   넣어 손제작 fixture와 실도면 사이의 대표성 간극을 게이트 안에서 닫는다.
   **기대값의 출처가 관건이다(적대 점검)**: R-real의 기대 결선을 체크인된
   파이프라인 출력(`results/*.json`)에서 가져오면 **현재 동작을 정답으로
   박제**하는 순환이 된다. 기대값은 반드시 p14 **adjudicated 라벨의
   relations**에서 가져온다 — 라벨이 심판이고 출력은 피심판이다.
3. **flake 규율**: 재시도로 green 만들기 금지. flaky 게이트는 DORMANT 대장
   방식의 격리 항목으로만 제외 가능(사유·소유·복귀 조건 기록).
4. **승격 조건**: `live-gates` 14일 연속 green 후 required check로 승격.
   그 전에는 required로 만들지 않는다 — 불안정한 게이트를 필수로 만들면
   우회 관행이 생기고 그게 55점의 원인이다.

#### W3 — 재현성 60 → 90

두 번의 드리프트(ts-node 부재, gate:pdf 로컬 17/17 vs CI 6/17)가 원인이다.
공통 뿌리: **개발 머신의 node_modules가 lockfile과 어긋나도 아무것도 막지
않는다.**

1. **환경 동등성 게이트** (`scripts/verify-env-parity.mjs`, enforce.ps1 첫
   단계): node 버전 = `.nvmrc` ∧ `npm ls` 정합 ∧ lockfile working-tree clean.
   **`npm ls`만으로는 부족하다(적대 점검)** — `npm ls`는 설치 트리가
   package.json과 정합인지 보지, **어느 lockfile로 설치됐는지**는 모른다.
   ts-node 드리프트가 정확히 이 틈이었다. 보강: `npm ci` 성공 시 postinstall이
   lockfile SHA-256을 스탬프 파일(`node_modules/.esa-lockfile-stamp`)에
   기록하고, 동등성 게이트는 현재 lockfile 해시와 스탬프를 대조한다.
   스탬프 부재·불일치 = "이 트리는 현재 lockfile로 clean install된 것이
   아니다" → 이후 단계 차단. "내 머신에서는 됐다"를 기계적으로 불가능하게
   만든다.
2. **`packageManager`·`engines` 고정**: package.json에 npm 버전과 node 범위를
   선언해 corepack/설치기가 강제하게 한다.
3. **CI 정본 규율**: PROJECT_STATE '검증'에 올리는 exit 0은 CI run ID를
   인용한다. 로컬 실행은 참고로만 기록한다. (이 PR에서 이미 실행 중인 관행의
   명문화.)
